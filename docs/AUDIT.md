## 实际实现

1. 固件入口为原始 `Ant/god.c`，工程 `Ant/KGOD.uvproj` 仅列出该 C 文件，启动代码依赖 Keil 工具链。没有发现当前主工程自行维护的汇编源文件。课程阶段工程属于另一批教材任务，不纳入本仓库。
2. `src/q_learning.py` 实现 Q 表、ε-greedy、终止/非终止 Bellman 更新和 JSON 保存；`train.py` 逐回合调用环境并更新 Q，具有真正的强化学习训练机制。没有神经网络、DQN、PPO 或实车在线学习。
3. 环境、奖励和模拟参数集中在 `src/environment.py`，算法超参数由 `train.py` 的函数默认值与命令行参数配置，没有独立 YAML 配置。保存的训练汇总为 6000 回合、seed 0、α=0.1、γ=0.95、ε 下限 0.05；这些是读取已有文件得到的历史信息。
4. 已保存 Q 表、6000 回合 CSV、训练汇总、两份评估 JSON、策略头文件和量化 Q 头文件；没有大型神经网络权重或独立数据集。现有 BAT 依次运行测试、训练、评估、导出，其“测试”也含训练，故本次未执行。

## 发现的问题（保留原代码，不在本次修复）

| 问题 | 代码证据与影响 |
| --- | --- |
| 评估策略标签错误 | `evaluate()` 在未提供 `action_fn` 时先定义内部函数，后续再以 `if action_fn` 选择标签，因此 Q-learning 和规则评估都会标成 `god_c_rule`；终端标签也受影响。两份历史 JSON 均受此问题影响。 |
| 基线不是完整固件 | `god_c_rule_action(0)` 只返回 BACK，没有固件的 `last_dir` 记忆和后退后转向恢复；环境每动作采用统一 DT，也未复现 STEP_TURN/STEP_TRIM 等持续步数。 |
| 兜底状态判断有限 | `build_policy()` 根据某行是否存在非零 Q 值推断学习覆盖，不记录实际访问计数。当前有 8 个全零行，导出策略用规则补齐；不能把 16 行全部称为学得的策略。 |
| 历史文档过时 | 原 Ant README 仍出现中值 1400、转向速度 500 等旧描述；当前代码为 1520 和 450，源码部分动作示例注释也保留旧数值。新 README 以宏与函数实现为准。 |
| 时钟不一致 | 原 uart.h 定义 XTAL=11059200，工程 XML 的 CPU CLOCK(33000000)。此处记录差异，没有擅自更改，也没有测量实物晶振。 |
| 权利范围不明确 | 原 AT89X52.H 含 Keil 版权所有声明；uart.h、Boebot.h 被原文档标为厂商原版，未找到明确再分发许可。本次排除三者，改为说明外部依赖。 |
| 训练 BAT 可移植性和错误处理 | 原 BAT 写死旧相对目录，训练、评估、导出之后没有逐步阻断失败。它未上传，发布副本提供适配新目录且检查退出码的显式训练入口。 |
